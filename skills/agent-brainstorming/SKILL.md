# Agent Brainstorm

将模糊的 Agent 想法转化为完整的设计规格，通过身份审问识别并拒绝伪 Agent 需求。

<HARD-GATE>
不得跳过身份审问（Phase 0）直接进入设计。身份审问是硬性前置条件，失败则终止流程。
不得在用户批准设计规格之前生成任何文件或调用 writing-plans。
</HARD-GATE>

## Checklist

按顺序创建 task 并逐一完成：

1. **Phase 0：身份审问** — 4 道必答题，通过才能继续
2. **Phase 1：角色定义** — 精化角色名、专业领域、输出所有权
3. **Phase 2：Skill 依赖映射** — 列出所需能力，标记已有/缺口
4. **Phase 3：推理循环设计** — 确定类型、最少迭代数、停止条件
5. **Phase 4：输出规格设计** — 输出形态、模板结构
6. **Phase 5：规格生成** — 生成设计规格文档，提交，调用 writing-plans

## Phase 0：身份审问（Hard Gate）

逐一提问，每次只问一道，等待回答后再问下一道：

> Q1：用一个职业或职能词语描述这个 Agent 是谁？（例如：股市分析师、代码审查官）

> Q2：它需要做哪些"无法脚本化"的判断？请描述至少一个具体场景。

> Q3：任务结束后，这个 Agent 对什么结果负责？谁会用这个输出做决策？

> Q4：如果这是一个人类专家，他需要什么专业背景？

**判定规则：**

- Q1 的答案听起来像工具/能力/功能（"PDF 阅读器"、"数据抓取器"）→ **失败**
- Q2 举不出具体的无法脚本化的判断 → **失败**
- 失败时终止并告知：

> 根据身份审问，这个需求无法映射到明确的 Agent 角色。它更适合作为 Skill 实现。
> 建议使用 skill-brainstorm 重新设计。

通过后继续 Phase 1。

## Phase 1：角色定义

基于 Phase 0 的答案，逐步确认：

- 角色名（简洁的职业描述）
- 专业领域（这个角色的知识边界在哪里）
- 签名输出（Agent 完成任务后交付什么，以什么形式"署名"）

每次只问一个确认问题。

## Phase 2：Skill 依赖映射

询问这个 Agent 需要哪些外部能力，逐一确认：

> 这个 Agent 要完成任务，需要访问哪些外部系统或执行哪些操作？
> （例如：搜索网页、读取文件、调用 API、操作浏览器）

对每项能力：
- 是否已有对应 Skill？
- 若无 → 标记为「缺口：需要先开发 Skill: <name>」

继续设计，不因缺口终止，但在规格中显式标注。

## Phase 3：推理循环设计

逐步确认：

> 这个 Agent 的工作是一次性完成，还是需要多轮迭代？

若迭代：
> 最少需要几轮才能保证质量？停止的条件是什么？

## Phase 4：输出规格设计

> 这个 Agent 最终交付什么？是一份报告、一个裁决、还是结构化数据？

确认输出形态后，草拟输出模板结构（用占位符表示）。

## Phase 5：规格生成

加载 `assets/agent-design-template.md`，按模板填写各节内容后写入：

```
docs/design/YYYY-MM-DD-<agent-name>-design.md
```

提交设计文档，然后：

> 设计规格已写入 `<path>`，请确认无误后我们继续制定实现计划。

等待用户确认，然后调用 **writing-plans** skill。

## 关键原则

- **一次一个问题** — 不堆叠多个问题
- **身份审问不可跳过** — 再简单的 Agent 需求也要过 Phase 0
- **缺口不阻塞设计** — 标记缺口，继续推进
- **规格优先于实现** — 设计文档批准前不生成任何代码文件
