# Expression Patterns

Refine Markdown toward concise, accurate, forceful SOP language.

## Prefer these moves

### 1. Replace explanation with instruction

Weak:

- "This section is intended to help the model understand..."

Stronger:

- "Use this section to..."

### 2. Replace commentary with constraints

Weak:

- "It may be useful to..."

Stronger:

- "Do this when..."

### 3. Replace drift with decision

Weak:

- long setup before the actual action

Stronger:

- lead with the action, then add only the minimum rationale

### 4. Replace soft wording with operational wording

Prefer:

- `Use`
- `Do not`
- `Keep`
- `Move`
- `Ask`
- `Present`
- `Stop`
- `Escalate`

Avoid overusing:

- "might"
- "perhaps"
- "it can be helpful"
- "generally speaking"

## Tone target

The target voice is:

- calm
- exact
- strong
- low-fluff

It should feel like an operator's playbook, not a teacher's essay.

## Keep this distinction clear

| Bad mode | Better mode |
|---|---|
| Explaining the document | Telling the reader what to do |
| Repeating obvious context | Naming the decision or action |
| Generic advice | Specific execution rule |
| Decorative prose | Functional prose |
