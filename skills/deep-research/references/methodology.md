# Methodology

`deep-research` 的核心不是"多搜几次"，而是按 Phase 有节奏地推进研究。

## Phase 0: Clarify Goal

先确认：

- 用户是要学习、做决策，还是生成内容
- 时间范围、对象范围、比较范围
- 最终需要回答哪些问题

用户只说"研究一下 X"时，默认拆成 3-5 个子问题。

**澄清完成后立即产出 `plan.md`**：

```markdown
## Research Plan

1. [ ] <研究方向 1>（目的：<1 句话>）
2. [ ] <研究方向 2>（目的：<1 句话>）
3. [ ] <研究方向 3>（目的：<1 句话>）
```

控制在 3-6 条。每轮结束时更新 checkbox（`[ ]` → `[x]` 或 `[~]` 部分完成）。这份 plan 是每轮 Synthesis Check 的检查基准。

## Phase 1: Broad Exploration

先广后深。目标是画出维度地图，不做结论。

- 了解主题全貌、找关键维度
- 识别利益相关方、观点阵营、竞争对象、时间线
- 收集关键词、实体、专有术语

规则：

- 使用 `search-multi` 跨至少 **2 个互补平台**（见 `source-strategy.md` 平台矩阵）
- 中文与英文各搜至少一次
- 至少覆盖 2-3 个角度
- 这一阶段只看 snippet，不读全文

## Phase 2: Deep Dive

针对 Phase 1 识别的关键维度做定向深挖。

- 验证核心事实
- 读高价值来源全文（不只看 snippet）
- 跟进重要引用
- 根据上一轮结果优化 query：发现术语就精确搜；过泛加限定词；过窄换同义词
- 每个维度至少尝试 2 种 phrasing

**每次搜索前先输出 Pre-search Reasoning 块**（纯文字，不需要工具）：

```
[Pre-search Reasoning]
本轮目标：<验证什么 / 填补哪个 gap>
选择平台：<平台名>（原因：<1 句话>）
未选平台：<平台名>（原因：上轮已覆盖 / 边际收益低）
Query 设计：
  - "<query 1>" → <期望找到什么>
  - "<query 2>" → <期望找到什么>
```

它强制在行动前明确意图，防止重复搜索和方向漂移，对弱推理模型收益尤其大。

**回退条件**：Deep Dive 中发现 Phase 1 未识别的重要新维度或新子问题 → 立即更新 subquestions，回 Phase 1 补广度探索。单一方向连续深挖 3 轮以上而未做广度检查是反模式。

## Phase 3: Diversity And Validation

主动补齐盲区，不要只沿一个角度深挖。

要覆盖的类型：

- 事实与数据
- 真实案例
- 专家观点
- 趋势与预测
- 对比与替代方案
- 风险、限制、反对意见

## Phase 4: Synthesis Check

每轮结束输出固定格式状态块（**不可省略**）：

```
[Round N Synthesis]
已闭合：<子问题编号> ✓（来源：<URL 或来源名>），<子问题编号> ✓（来源：...）
仍开放：<子问题编号>（现状：<找到了什么，缺什么>），<子问题编号>（未开始）
矛盾：<来源 A> 与 <来源 B> 在 <X> 上有分歧，需第三方仲裁 / 无矛盾
平台覆盖：已覆盖 <平台列表>，中文 <是/否>，英文 <是/否>
下一轮目标：<具体要验证什么 / 填补什么 gap>
```

对照 `plan.md` 更新每条的 checkbox。研究不是"搜到就停"，而是"核心问题被回答后才停"。

## Handling Contradictions

两个来源对同一事实给出相反说法时：

1. **必须仲裁**：找第三个独立来源判断哪方更可信
2. **无法仲裁则双方保留**：在报告中并列呈现并标注"存在分歧"
3. **记录矛盾**：`source_note` 里用 `contradicts` 字段指向对方
4. **限制信心**：存在未解决矛盾时 hypothesis 的 confidence 不得为 `high`
5. **矛盾即价值**：往往是最有价值的发现，报告里"关键分歧"部分重点呈现
