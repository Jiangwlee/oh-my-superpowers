# Methodology

`deep-research` 的核心不是"多搜几次"，而是有节奏地推进研究。

## Phase 0: Clarify Goal

先明确：
- 用户是想学习、做决策，还是生成内容
- 研究主题的时间范围、对象范围、比较范围
- 需要最终回答哪些问题

如果用户只说"研究一下 X"，默认把它拆成 3-5 个子问题。

**澄清完成后，立即输出研究计划**（写入 workspace 的 `plan.md`）：

```markdown
## Research Plan

1. [ ] <研究方向 1>（目的：<1 句话>）
2. [ ] <研究方向 2>（目的：<1 句话>）
3. [ ] <研究方向 3>（目的：<1 句话>）
```

计划控制在 3-6 条。每轮研究结束时更新对应条目的状态（`[ ]` → `[x]` 或 `[~]` 表示部分完成）。这份计划是每轮 Synthesis Check 的检查基准。

## Phase 1: Broad Exploration

先做广泛探索，不要一开始就钻得很深。

目标：
- 了解主题全貌
- 找出关键维度
- 识别主要利益相关方、观点阵营、竞争对象、时间线

要求：
- 使用 `search-multi` 跨至少 2 个互补平台搜索（参考 source-strategy.md 的平台选择矩阵）
- 中文和英文各搜至少一次
- 至少从 2-3 个角度搜索
- 先收集关键词、关键实体、专有术语
- 这一阶段不做全文阅读，只看 snippet 建立维度地图
- 不急于写结论

## Phase 2: Deep Dive

针对广泛探索中识别出的关键维度，做定向深挖。

目标：
- 验证核心事实
- 找到关键来源
- 获得足够深入的上下文

要求：
- 每个维度至少尝试 2 种 query phrasing
- 优先读高价值来源的全文，不只看 snippet
- 发现重要引用时继续跟进
- 根据上一轮结果优化查询词：发现专有术语时用术语精确搜；结果太泛时加限定词；结果太窄时换同义词

**搜索前先输出推理块**（不需要工具调用，纯文字）：

```
[Pre-search Reasoning]
本轮目标：<验证什么 / 填补哪个 gap>
选择平台：<平台名>（原因：<1 句话>）
未选平台：<平台名>（原因：上轮已覆盖 / 边际收益低）
Query 设计：
  - "<query 1>" → <期望找到什么>
  - "<query 2>" → <期望找到什么>
```

这个步骤强制在行动前明确意图，防止重复搜索和方向漂移。对弱推理模型收益尤其大。

**回退条件**：如果 deep dive 中发现了 Broad Exploration 未识别的重要新维度或新子问题，应立即更新 subquestions，并回到 Phase 1 补充该维度的广泛探索。不要在单一方向上持续深挖超过 3 轮而不做广度检查。

## Phase 3: Diversity And Validation

主动补齐研究盲区，不要只沿着一个角度深挖。

要覆盖的类型：
- 事实与数据
- 真实案例
- 专家观点
- 趋势与预测
- 对比与替代方案
- 风险、限制、反对意见

## Phase 4: Synthesis Check

每轮结束时输出固定格式的状态块（不可省略）：

```
[Round N Synthesis]
已闭合：<子问题编号> ✓（来源：<URL 或来源名>），<子问题编号> ✓（来源：...）
仍开放：<子问题编号>（现状：<找到了什么，缺什么>），<子问题编号>（未开始）
矛盾：<来源 A> 与 <来源 B> 在 <X> 上有分歧，需第三方仲裁 / 无矛盾
平台覆盖：已覆盖 <平台列表>，中文 <是/否>，英文 <是/否>
下一轮目标：<具体要验证什么 / 填补什么 gap>
```

对照 `plan.md` 检查每条计划项的状态，更新 checkbox。

研究不是"搜到结果就停"，而是"核心问题足够被回答后才停"。

## Handling Contradictions

当两个来源对同一事实给出矛盾说法时：

1. **必须仲裁**：寻找第三个独立来源来判断哪方更可信
2. **无法仲裁时保留双方**：在报告中保留双方观点并标注"存在分歧"
3. **记录矛盾**：在 source_note 中用 `contradicts` 字段记录与哪个 source 矛盾
4. **限制信心**：hypothesis 的 confidence 在存在未解决矛盾时不得为 "high"
5. **矛盾是价值**：矛盾本身往往是最有价值的发现，应在报告的"关键分歧"部分重点呈现
