## 1. 体系目标与假设

**目标**：在“东方财富人气前 1000（默认，可配置）”中捕捉**强趋势的延续段**，通过“回撤低吸 + 确认再启动 + 快速止损”提高赔率与可执行性，解决现在的痛点：

* 只在 5/10 日线附近小仓买到但赚不到；
* 后续加仓又经常赶上见顶。

**交易周期**：日线执行为主（信号日级），周线用于结构过滤与动态止损线（MA5W）。
**持仓周期**：数天到数周。
**风险约束**：单笔快速止损 3%~5%（可配置）。

---

## 2. 数据与指标（全部量化定义）

对每只股票，至少需要：

* 日线 OHLCV：最近 ≥ 120 交易日
* 周线 OHLCV：最近 ≥ 60 周（或由日线聚合）
* 实时价/当日成交量（盘中仅用于“候选观察”，最终触发以收盘价为准更稳定）
* 市场环境：涨停/跌停家数等（代码已有 `MarketSentiment`）

### 2.1 均线

* `MA20D(t)`：最近 20 个交易日收盘价均值
* `MA50D(t)`：最近 50 个交易日收盘价均值
* `MA5W(w)`：最近 5 周周收盘价均值（周线）
* `MA20W(w)`：最近 20 周周收盘价均值（周线）

### 2.2 乖离率（用于识别“加速末端”）

* `DEV20W = (CloseW - MA20W) / MA20W`
* `DEV20D = (CloseD - MA20D) / MA20D`

### 2.3 量能比（替代“缩量/放量”的模糊说法）

* 日量能比：`VR20D = VolD_today / AVG(VolD, 20)`
* 周量能比：`VR5W = VolW_this / AVG(VolW, 5)`

> 量能的“缩/放”统一用阈值描述：
>
> * “缩量”定义为 `VR20D <= 0.70`
> * “放量”定义为 `VR20D >= 1.50`
>   也可以改成 0.8/1.3 这种更宽松阈值，但必须固定。

### 2.4 回撤区间高点/低点（用于“回撤结束确认”）

当出现一次回撤过程（见 4.1 的 Setup），定义：

* `PB_HIGH = max(HighD, 回撤开始日至当前日)`
* `PB_LOW  = min(LowD,  回撤开始日至当前日)`

回撤结束确认的核心触发就是“突破 PB_HIGH”。

## 3. 股票池与过滤（Universe & Regime）

### 3.1 股票池（Universe）

每天从东方财富“人气榜”取前 N=1000（默认，可配置）。

### 3.2 基础过滤（必须全满足）

对每只股票在日线收盘后计算：

1. **趋势存在**

* `CloseD > MA20D` 且 `MA20D(t) > MA20D(t-5)`（MA20D 过去 5 天上行）

2. **周线方向一致**

* `CloseW > MA5W` 且 `MA5W(w) > MA5W(w-3)`（MA5W 相比 3 周前上行）

3. **流动性过滤（可选但建议）**

* `AVG(Amount, 20) >= X`（例如 2 亿或 5 亿，阈值自己定，必须写死或参数化）

### 3.3 市场环境过滤（Regime）

代码已有 `danger_level`（yellow）。这里量化为：

* 若 `danger_level == "yellow"`：所有入场信号阈值提高（例如 +10 分）或直接降低最大仓位（见 6.1）。
* 或者简单规则：`limit_down >= 50` 时，不开新仓（只允许减仓/止损）。

## 4. 入场体系（分两段：Setup → Trigger）

现在“买早”的根本原因：**把 Setup 当 Trigger**（回到 MA5W 附近就直接买），但回撤可能还没结束。

所以我们把入场拆成两段，全部量化。

---

### 4.1 Setup：定义“可低吸的健康回撤”（进入观察状态）

当满足 3.2 的趋势过滤后，若出现以下条件，则标记为 `PULLBACK_SETUP = True`：

**条件 A（回撤触发）**：

* `DEV5W = (CloseD - MA5W) / MA5W`
* `abs(DEV5W) <= 0.03`（回到 MA5W ±3% 区间）

**条件 B（回撤强度不过度）**：二选一

* `Drawdown = (HighestCloseD_20 - CloseD) / HighestCloseD_20 <= 0.12`
  （近 20 日从最高收盘回撤不超过 12%）
  或
* `CloseD >= MA20D`（仍在 MA20D 上）

**条件 C（抛压衰减 = 量能比下降）**：

* `VR20D <= 0.80`（当日量能不高于 20 日均量的 0.8）

> 只要 A + (B) + C 成立：进入“观察回撤”状态。
> 注意：这里完全不出现“缩量”这个词，只有 VR20D 阈值。

一旦进入 Setup，记录：

* `pb_start_date`（setup 首日）
* `PB_HIGH`、`PB_LOW` 动态更新（见 2.4）

---

### 4.2 Trigger：回撤结束确认（真正的买点）

**真正的买点**不是“到了 MA5W”，而是：

> 在回撤 Setup 期间，价格重新向上突破 PB_HIGH，并伴随量能回归

量化 Trigger：

* `CloseD_today > PB_HIGH * (1 + 0.003)`（突破回撤区间高点 0.3% 以上，避免假突破）
* 且 `VR20D_today >= 1.10`（量能回到 20 日均量以上的 1.1）
* 且 `CloseD_today > OpenD_today`（收阳确认，避免冲高回落）

满足即触发：`ENTRY_SIGNAL = BUY`

> 可以把 0.3% 改成 0.5%，把 1.10 改成 1.05/1.20，但一旦确定就固定参数化。

## 5. 加仓体系（解决“后面加仓遇到见顶”）

现在的加仓经常发生在“看起来更安全、但其实更接近顶部”的阶段。
正确做法是：**加仓只发生在结构安全区，不发生在加速区。**

### 5.1 加仓触发（Add-on Trigger）

在首次买入后，允许一次加仓（最多一次），条件：

* `CloseD > EntryPrice * (1 + 0.03)`（浮盈至少 3%）
* 且 `CloseD > HighestCloseD_since_entry * (1 + 0.002)`（再创新高 0.2%）
* 且 `DEV20W <= 0.20`（距离 MA20W 乖离不超过 20%，防止加速末端加仓）

触发则 `ADD_SIGNAL = ADD`

### 5.2 加速区禁止加仓（Hard Ban）

任意满足两条，进入“加速区”，禁止新开仓/禁止加仓（只允许移动止盈/减仓）：

* `DEV20W > 0.25`
* `DEV20D > 0.15`
* 最近 3 周中有 2 周 `WeeklyReturn > 0.10`（周涨幅>10%）
* 最近 10 日中有 3 日 `DailyReturn > 0.06`

## 6. 仓位与风控（全部量化）

### 6.1 仓位（Position Sizing）

采用两段建仓，避免“一次性50%在加速末端上车”。

* 首次入场：`pos1 = 25%`（或 30%）
* 加仓：`pos2 = 25%`（使总仓位达到 50%）
* 若 `danger_level == yellow`：`pos1 = 15%`，且禁止加仓（或总仓位上限 30%）

### 6.2 初始止损（Fast Stop）

首次买入后立即定义止损价（取更紧的那个）：

* `Stop1 = EntryPrice * (1 - 0.04)`（4% 固定止损）
* `Stop2 = PB_LOW * (1 - 0.01)`（回撤低点下方 1%）

最终止损：`STOP = max(Stop1, Stop2)`（离得更近的止损更“紧”，但这里取 max 是为了不让止损离太远）

触发规则（T+1现实）：

* 若当日收盘 `CloseD < STOP` → 次日集合竞价/开盘卖出（执行层自行实现）

### 6.3 动态止盈 / 趋势止损（基于 5 周线）

持仓后，采用周线生命线，但必须量化“跌破”：

* **有效跌破 MA5W**：`CloseW < MA5W * (1 - 0.015)`（周收盘跌破 1.5%）
  触发：减仓 50% 或清仓（看风格）

* **连续两周有效跌破**：两周均满足上式
  触发：清仓

> 这比“盘中跌破就算”稳定得多，也符合“周线体系”。

### 6.4 分批止盈（防止利润回吐）

当满足任意一条，减仓 50%：

* `CloseD > MA5W * 1.25`（代码已有 25% 超涨减仓，保留）
  或
* `DEV20W > 0.30`（周线乖离过大）

剩余仓位用 5 周线规则跟踪退出。

## 7. 每日工作流（可落地到程序）

1. **收盘后**：更新日线/周线指标
2. 从人气前500中筛出满足趋势过滤的股票
3. 对每只股票判断是否进入 `PULLBACK_SETUP`，如是则更新 PB_HIGH/PB_LOW
4. 对处于 Setup 的股票判断是否触发 `ENTRY_SIGNAL`（突破 PB_HIGH + VR20D条件）
5. 对持仓股票：

   * 判断是否触发 `FAST STOP`（日线）
   * 每周五额外判断是否触发 `MA5W有效跌破`（周线）
   * 判断是否触发减仓条件（超涨/乖离过大）

## 8. 输出信号规范（给 assistant/计划用）

建议信号输出统一为结构化 JSON（已有 `watchlist_signals.json`，继续沿用）：

* `state`: `"NONE" | "SETUP" | "ENTRY" | "HOLD" | "ADD" | "REDUCE" | "EXIT"`
* `pb_start_date`
* `pb_high`, `pb_low`
* `ma5w`, `ma20w`, `ma20d`
* `vr20d`, `dev20w`, `dev5w`
* `entry_price`, `stop_price`
* `position_target`（如 0.25 / 0.50）
* `action_next_day`（T+1执行建议）

这样就能让 `ashare-assistant` 做“复盘 + 明日计划”时完全自动化。

# 9. 代码优化建议（基于当前 ashare-data）

下面是我对现有 `ashare_data/watchlist_monitor.py` 的**关键问题与可落地改法**（全部指向“量化、明确、可实现”）：

---

### 9.1 统一“跌破 5 周线”的定义：禁止盘中一刀切

现在 `_analyze_signal()` 里有硬过滤：

* `if current < ma5_week: return None`（盘中价跌破就直接排除）

但在 `_check_exit_signals()` 里又是：

* `if close < ma5_week: stop_loss`（收盘价）

**这会造成体系自相矛盾**：
最好的“下影线触线”低吸点，盘中可能短暂 `< MA5W`，但收盘收回。却直接过滤掉了。

✅ 改法（量化）：

* 将入场过滤改为：

  * 允许 `current >= ma5_week * (1 - intraday_break_allow)`
  * 例如 `intraday_break_allow = 0.02`（允许盘中刺破 2%）
* 真正的“跌破=离场”只以周收盘 `CloseW < MA5W*(1-1.5%)` 判定（见 6.3）

---

### 9.2 把“缩量回调”改成量能比阈值字段（已经算了，但输出要结构化）

现有是：

* `vol_ratio = today_vol / avg_vol_20`
* `<0.7` 加分，`>1.5 且下跌`扣分

✅ 改法：

* 直接在信号里输出 `vr20d` 字段（现在 reasons 里只有“缩量回调”文字）
* 所有条件写成阈值判断：`vr20d <= 0.8`、`vr20d >= 1.5`，并在 config 可配置

---

### 9.3 增加“Setup → Trigger”的状态管理（解决买早）

现在的 `buy_dip` 基本是“接近 MA5W 就给买点”，缺少回撤结束确认。

✅ 改法（最关键）：

* 在 `~/.ashare-assistant/memory/` 增加一个 `pullback_state.json`
  保存每只股票是否处于 SETUP、以及 pb_start_date/pb_high/pb_low
* 在每次扫描时：

  1. 满足 Setup → 进入 SETUP，记录 pb_high/pb_low
  2. 满足 Trigger（突破 pb_high + vr20d>=1.1 + 收阳）→ 输出 ENTRY 信号
* 这样不会再“回到 5 周线就买”，而是“回到 5 周线进入观察，突破确认才买”。

---

### 9.4 加速末端过滤加入硬阈值（禁止见顶区加仓/开仓）

现在没有用 `MA20W` 与乖离率做硬过滤（只靠 MA20D/MA5W）。

✅ 改法：

* 增加周线 `MA20W`（从 weekly_bars 计算）
* 新开仓/加仓前必须满足：`dev20w <= 0.25`
* 若 `dev20w > 0.30` 直接输出 `reduce` 或至少降级为 `watch`

---

### 9.5 参数全部迁移到 config.json（让体系可调、可回测）

把这些阈值放到 `~/.ashare-assistant/config.json`：

* `dev5w_band = 0.03`
* `vr20d_shrink = 0.80`
* `vr20d_expand = 1.10`
* `intraday_break_allow = 0.02`
* `ma5w_break_week = 0.015`
* `fast_stop_pct = 0.04`
* `pb_breakout_buffer = 0.003`
* `dev20w_no_add = 0.20`
* `dev20w_no_trade = 0.25`

当前 `_load_app_config()` 已经写了，只需要真正用起来。
