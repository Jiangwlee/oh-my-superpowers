omp serve — 架构文档

Project-local Skill 工作台 · Python launcher + TypeScript 全栈应用 · 单进程 HTTP+WS server

scope: cli/serve/ · 生成日期 2026-06-14 · 事实来源：server/ + web/ + extensions/ + pty_helper.py

一句话

浏览器三栏工作台（文件树 / 编辑器·预览 / Pi 交互）经由一个 Node 单进程 server，把 Pi coding agent 的 JSONL 流转换成前端可消费的事件：聊天走 SSE，终端走 WebSocket（PTY 在 Python），生成式 UI 走 render_ui 扩展 + 沙箱 iframe。Python (main.py) 只做生命周期编排与按需构建，不参与任何请求。

1 · 分层架构

四个进程层，职责严格隔离。每个 /api/chat 或终端连接都会拉起一个独立的 Pi 子进程。

┌─────────────────────────────────────────────────────────────────────┐
│  BROWSER  (web/, 打包到 web/dist/bundle.js)                          │
│  三栏工作台：tree.ts · editor/markdown.ts · chat.ts/genui.ts/terminal.ts │
│  state.ts 单一可变状态 · api.ts fetch 封装                              │
└───────────┬───────────────────┬───────────────────┬───────────────────┘
   HTTP/JSON │           SSE     │      WebSocket     │
   /api/*    │       /api/chat   │     /ws/terminal   │
┌───────────▼───────────────────▼───────────────────▼───────────────────┐
│  NODE SERVER  (server/, 打包到 server/dist/index.js)                 │
│  index.ts 单一 HTTP+WS 入口 · config.ts 配置/路径 · sse.ts 响应助手     │
│  routes/{meta,tree,file,chat}  ·  fs/workspace.ts (路径越界防护)        │
│  pi/runChat.ts (spawn pi)  ·  pi/events.ts (JSONL→SSE 映射)  ·  pi/terminal.ts (WS↔PTY) │
└───────────┬───────────────────┬───────────────────┬───────────────────┘
            │ spawn pi -p        │ spawn pi          │ spawn python3
            │ --mode json        │ (--extension)     │ pty_helper.py
┌───────────▼────────────────────────────────┐ ┌────▼───────────────────┐
│  PI CODING AGENT (子进程, 每次请求一个)       │ │ pty_helper.py (Python) │
│  stdout 输出 JSONL 事件流                    │ │ 持有真实 PTY，运行交互   │
│  --extension render_ui.ts 注册 render_ui 工具 │ │ 式 pi，NDJSON 桥接       │
└─────────────────────────────────────────────┘ └────────────────────────┘

各层职责

层文件职责
Python launchermain.pytyper CLI（start/stop/restart）、PID/端口/后台 spawn、stale 时跑 node build.mjs、拉起 node server/dist/index.js 并透传 host/port/model/workspace。不处理任何请求。
Node 入口server/index.ts单 createServer：静态文件（web/dist，防路径穿越）+ JSON/SSE 路由分发 + upgrade 事件转给终端 WS。
配置server/config.ts从 argv 读 host/port/model/workspace；派生 RENDER_UI_EXTENSION_PATH、PTY_HELPER_PATH、WEB_DIST_DIR、session 目录（<workspace>/.omp/serve/sessions/）。model 默认 OMP_DEFAULT_MODEL_PI 兜底。
事件映射server/pi/events.ts核心翻译层：把一行 Pi JSONL 解析成 0..N 个 SSE 事件。per-stream createPiLineMapper() 隔离 render_ui 缓冲状态。
聊天流server/pi/runChat.tsspawn pi -p --mode json --approve --extension render_ui，按行喂给 mapper，转 SSE；客户端断开/agent_end 时 SIGTERM→SIGKILL 收尾。
终端桥server/pi/terminal.ts零依赖手写 WebSocket（握手/帧编解码），spawn pty_helper.py，双向桥接 NDJSON。
PTY 宿主pty_helper.pyopenpty 运行交互式 pi --approve，select 循环，TIOCSWINSZ resize，进程组 teardown。PTY 逻辑留在 Python。
Pi 扩展extensions/render_ui.ts注册 render_ui 工具（CopilotKit 式 envelope）：LLM 把完整 HTML 文档放进工具参数，handler 是 no-op，真正渲染由 server 拦截参数流 + 前端沙箱 iframe 完成。
前端web/*.tsvanilla TS：tree / editor / markdown / chat / genui / terminal / state / api。打包成 web/dist/bundle.js。

2 · 消息流向

2.1 文件 / 树（同步 JSON）

GET  /api/meta   → {workspace, model, sessionMode:"page-local"}
GET  /api/tree?path= → routes/tree → fs/workspace.listDirectory → {path, nodes, count}
GET  /api/file?path= → 读文本（resolveRel 路径越界防护）→ {path, content}
PUT  /api/file   → 写文本：O_NOFOLLOW 防 symlink 越界，fd 级 write+truncate

所有路径经 fs/workspace.resolveRel 限定在 workspace 内；写入用 O_NOFOLLOW 防 check→open 之间被换成符号链接（路径逃逸红线）。

2.2 聊天（异步 SSE，生成式 UI 的主通道）

// 浏览器 → server → pi → server → 浏览器，单向流
chat.ts sendMessage()
  → POST /api/chat {message, sessionId}
    → routes/chat 校验 → runChat.handleChat
      → spawn pi -p --mode json --approve --extension render_ui --session <id>.jsonl --model M
        → pi stdout: 一行行 JSONL 事件
          → events.mapPiLine(line) // 翻译为 SSE
            → sse.sendSse: data: {type:...}\n\n
              → chat.ts 读 ReadableStream，按 \n\n 切分，dispatch
                → assistant_delta → appendAssistant（markdown 渲染）
                → tool_start/tool_end → timeline step
                → gen_ui_delta / gen_ui → genui.ts postMessage → 沙箱 iframe
                → done → 解锁输入框
  客户端断开 res.on("close") 或 agent_end → kill pi（SIGTERM→2s→SIGKILL）

2.3 终端（双向 WebSocket，PTY 在 Python）

terminal.ts → WS /ws/terminal?sessionId=
  → index.ts upgrade → terminal.handleTerminalUpgrade（手写握手）
    → spawn python3 pty_helper.py --session --model --cwd
       浏览器 → server: WS text frame {type:"input"|"resize"} → helper stdin (NDJSON)
       helper → server → 浏览器: stdout {type:"output"} → WS text frame
                                            {type:"exit"} → WS close
    close/error → helper.kill(SIGTERM)

4 · render_ui 生成式 UI（最精巧的一环）

难点：Pi 把整份 HTML 作为工具参数流式吐出（可能是增量片段，也可能是累积快照），且最终的「跑脚本」时机必须恰好一次——多跑会重复执行脚本，漏跑则交互失效。

服务端 (events.ts) 的恢复策略

  • 流式阶段：toolcall_delta 里 extractHtmlFromPartialJson 从不完整 JSON 中尽力抠出 html 值（容忍截断尾巴），发 gen_ui_delta。区分增量片段 vs 累积快照（以 {/[ 开头则重置缓冲）。
  • START 兜底：Pi 在 start 而非 end 携带完整 html，故在 tool_execution_start 缓存 renderState.lastHtml，覆盖无 toolcall_delta 的快流。
  • 权威 END：仅在 tool_execution_end 发出一次 gen_ui（run=true）。优先 materialized args → 缓冲 JSON → renderState.lastHtml 三级 fallback。
  • per-stream renderArgBuffers + renderState，并发 chat 不串味。

前端 (genui.ts) 的无闪烁 + 防误擦

  • 持久 shell iframe（GENUI_SHELL，沙箱）只建一次；内部 bootstrap 收 postMessage，原地改 head/body，永不重新导航 → 无白闪。
  • run 标志：delta 帧 run=0 只渲染不跑脚本；最终帧 run=1 严格按顺序执行脚本（外部脚本 onload 串行），全跑完才派发 DOMContentLoaded / load。
  • seal 机制：run=true paint 后已挂事件监听器，任何迟到的 partial（run=false）会 innerHTML= 抹掉监听器——故 sealed 后忽略 partial，直到下一轮 resetGenUiSeal()（每条用户消息触发）。
  • 版本号：单调 genUiRenderVersion，节流中的旧 delta 若被新 render 抢先则丢弃，防覆盖最终脚本化渲染。

5 · 关键约束与不变量

  • 单进程 Node 一个 createServer 同时服务静态资源、JSON API、SSE、WS upgrade。
  • 无原生依赖 WebSocket 手写帧编解码，不引 ws；PTY 用 Python pty，不引 node-pty。
  • 路径越界防护 所有文件操作经 resolveRel；写入 O_NOFOLLOW；静态服务拒绝 ..。
  • 每请求独立 Pi 一个 chat / 一个终端连接 = 一个 pi 子进程；断连必杀（SIGTERM→2s→SIGKILL）。
  • session 隔离 sessionId 正则 [A-Za-z0-9._-]{8,80}，落 <workspace>/.omp/serve/sessions/<id>.jsonl；sessionMode: "page-local"。
  • 沙箱渲染 render_ui HTML 在无 same-origin 的 iframe 里运行，库须走 CDN，不能用 localStorage/cookie/同源 fetch。
  • Python 不碰请求 main.py 只做 lifecycle + build-if-stale；运行期请求全在 Node。
